# start.md - AI 行为启动入口

> **定位**: 入口索引，告诉 AI "要做什么"
> **详细规范**: `@.iflow/endPoint.md`（告诉 AI "怎么做"）

---

## 核心要点（必须记住）

- **流程**: 预检 → 确认 → 规划 → 执行 → 自检 → 沉淀
- **强制输出模板**: 必须填满表格，否则视为未完成
- **交互规则**: 只在需要人类补充数据时才询问，否则默认执行下一阶段
- **防止 AI 幻觉**: 每个阶段必须读取/更新 Cache，证据必须具体
- **身份文件**: 每次预检必须读取 identity.md / soul.md / user.md
- **用户交互记录**: 每次用户确认或补充数据，必须更新 Cache（避免待办遗漏）
- **路径引用**: 所有文件引用必须使用 `@.iflow/...` 格式（完整路径），禁止使用相对路径或纯文件名

---

## 主动识别指令（强制执行）

**原则**：AI 在协作过程中主动识别需要读取的文件，贯穿整个协作周期。

### 识别规则

| 触发场景 | AI 必须主动识别 | 读取文件 |
|---------|---------------|---------|
| 任务开始 | 是否新项目？ | `@.iflow/context/experience/cold-start.md` |
| 理解有歧义 | 需要方法论？ | `@.iflow/context/experience/collaboration-method.md`（笛卡尔、乔哈里窗） |
| 涉及多文件 | 需要联动检查？ | `@.iflow/context/experience/collaboration-method.md`（联动检查章节） |
| 遇到未知问题 | 如何探索？ | `@.iflow/context/experience/collaboration-method.md`（PDCA章节） |
| 任务完成 | 如何沉淀？ | `@.iflow/context/experience/collaboration-method.md`（情境记忆法） |
| 参考历史经验 | 有类似案例？ | `@.iflow/context/experience/deposition-records.md` |

### 强制执行点

**每个阶段结束时，AI 必须输出**：

``` text
### 主动识别检查
- 是否有需要读取的经验文件？是/否
- 如果是：[文件名] - [原因]
```

**用户交互后，AI 必须更新 Cache**：

``` text
### Cache 更新
- 用户确认/补充：[内容摘要]
- 更新文件：task-progress.json
```

## 一、强制输出模板

### 触发条件（必须判断）

AI 在预检阶段必须首先判断是否使用模板：

| 场景 | 是否使用模板 | 原因 |
|------|-------------|------|
| 修改 .iflow 文件 | ✅ 必须 | 涉及 AI 协作规范，无编译验证 |
| 修改代码文件 | ❌ 不必须 | 有编译验证 |
| 单次简单问答 | ❌ 不必须 | 无需跨对话 |
| 跨对话任务 | ✅ 必须 | 需要 Cache 支持 |

**必须输出**：

``` text
### 是否使用强制输出模板？
- 判断：是/否
- 原因：[具体原因]
```

### 预检模板（触发时必须填空）

**第一步：身份初始化检查（强制）**

``` text
### 身份初始化
- 读取 `.iflow/context/identity/user.md`
- 状态：[不存在/待初始化/已初始化]
- 如果不存在或待初始化 → 读取 IDENTITY_SPEC.md → 输出询问 → 创建 user.md
```

**第二步：身份文件确认（强制）**

``` text
### 身份文件确认
- identity.md：[已读取/未读取]
- soul.md：[已读取/未读取]
- user.md：[已读取/未读取]
- 用户画像状态：[已初始化/未初始化]
```

**第三步：读取 Cache（强制）**

``` text
### Cache 读取
- task-progress.json：[有/无] current_task
- pending-tasks.json：[有/无] 待确认任务
- 如果有 current_task → 输出任务边界，询问是否继续
```

**第四步：四层防御检查**

``` text
## 预检

### 1. 四层防御检查
| Level | 名称 | 检查结果 | 是否读取 |
|-------|------|---------|---------|
| 0 | Cache 状态层 | 有/无待办 | ✅/❌ |
| 1 | 项目级冷启动 | 是否新项目 | ✅/❌ |
| 2 | 需求级冷启动 | 是否新需求 | ✅/❌ |
| 3 | 任务级执行清单 | 是否需要 | ✅/❌ |

### 2. 加载策略确认
- 稳定层：identity.md, soul.md, user.md, start.md, endPoint.md
- 动态层：cache/, experience/, skills/, app-demand/
- 本次加载：[列出实际加载的文件]

### 3. 概念阻塞
- 是否有概念阻塞：无 / 有（需说明）

### 4. 操作意图
- 意图：修改规范 / 修改代码 / 沉淀经验 / 创建文档

### 5. 必须读取文件
- [ ] 文件1
- [ ] 文件2

### 6. 已读取摘要
- @文件1：xxx
- @文件2：xxx
```

### 自检模板

``` text
## 自检

### 1. 规则检查表
| 规则 | 检查结果 |
|------|---------|
| 规则0 | ✅/❌ + 说明 |
| 规则1 | ✅/❌ + 说明 |
| 规则4 | ✅/❌ + 说明 |
| 规则9 | ✅/❌ + 说明 |

### 2. 核心原则检查（修改.iflow文件时必须）
| 原则 | 是否遵守 | 说明 |
|------|---------|------|
| 先规划后编码 | ✅/❌ | 是否输出了任务边界？ |
| 最小化上下文负载 | ✅/❌ | 是否只读取了必要文件？ |
| 始终以验证结束 | ✅/❌ | 是否输出了检查表？ |
| 意图门控 | ✅/❌ | 是否判断了操作意图？ |

### 3. 自指检查（提出新方法时必须）
| 提出的方法 | 是否执行 | 证据 |
|-----------|---------|------|
| 方法1 | ✅/❌ | 具体证据 |

### 4. AI幻觉检查（修改.iflow文件时必须）

| 幻觉类型 | 是否存在 | 证据 |
|---------|---------|------|
| 执行幻觉 | ✅/❌ | 输出了具体表格/一句话带过 |
| 读取幻觉 | ✅/❌ | 输出了内容摘要/只说"已读取" |
| 检查幻觉 | ✅/❌ | 输出了检查结果表格/只说"已检查" |
| 自指幻觉 | ✅/❌ | 验证了自己是否执行/没有验证 |

**判断标准**：
- ✅ 不存在幻觉 = 输出了具体表格和证据
- ❌ 存在幻觉 = 一句话带过，没有具体证据

### 5. 心跳检查（含 Cache 验证）

**第一步：读取 Cache 验证执行结果**

``` text
### Cache 验证
- current_task.completion_conditions：[检查每个条件状态]
- 如果有未完成条件 → 输出"未完成：xxx"，不能声称完成
```

**第二步：心跳检查表**

``` text
| 检查项 | 结果 | 证据 |
|-------|------|------|
| Cache 任务进度 | x/x | 读取 task-progress.json |
| 待办事项 | 无/有 | 读取 todo 状态 |
| 经验沉淀 | 无需/需沉淀 | 是否有新经验 |
```

**关键**：证据必须具体，不能只写"已完成"。
```

## 二、交互规则（减少不必要的确认）

### 原则

只在需要人类补充数据时才询问，否则默认执行下一阶段。

### 规则表

| 场景 | AI行为 |
|------|--------|
| 有需要用户补充的数据 | 输出"需要补充：xxx"，询问 |
| 没有问题需要补充 | 直接执行下一阶段，不询问 |
| 关键操作（git commit等） | 必须确认 |
| 任务完成时 | 输出完整检查表，等待确认 |

### 示例

``` text
❌ 错误（频繁询问）：
预检完成。是否进入确认阶段？[Y/n]
确认完成。是否进入规划阶段？[Y/n]
规划完成。是否执行？[Y/n]

✅ 正确（只在需要时询问）：
预检 → 确认 → 规划（无问题）→ 执行
执行完成，是否提交？[Y/n]（关键操作需要确认）
```

## 三、关键检查点（强制）

| 关键操作 | AI 必须输出 | 人类介入 |
|---------|-----------|---------|
| 创建 md 文件 | "检查规则8，是否允许创建？" | 必须确认 |
| git commit | "检查规则6，是否允许提交？" | 必须确认 |
| git push | "检查规则6，是否允许推送？" | 必须确认 |
| 任务完成 | 输出完整规则检查表 | 必须确认 |
