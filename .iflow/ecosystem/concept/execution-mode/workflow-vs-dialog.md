# 工作流模式 vs 对话模式

> **定位**: 两种不同的 LLM 使用场景
> **L2 引用**: @.iflow/endPoint.md

---

## 定义

两种不同的 LLM 使用场景，需要不同的配置和行为。

## 对比

| 模式 | 时效性检查 | 上下文 | 典型场景 |
|------|-----------|--------|---------|
| **工作流模式** | 不需要 | 固定 | 报告生成、数据处理流程 |
| **对话模式** | 需要 | 动态 | 智能客服、对话机器人 |

## 使用场景

- **工作流模式**：固定流程、无需时效性、批量处理
- **对话模式**：动态交互、需要时效性、实时响应

## 混合架构选型原则

### LLM 接管程度划分

| 模式 | LLM 接管程度 | 灵活性 | 确定性 | 适用场景 |
|------|-------------|--------|--------|---------|
| **完全 ReAct** | 高（全流程） | 高 | 低 | 探索性任务 |
| **Workflow** | 中（部分阶段） | 中 | 中 | 结构化流程 |
| **传统代码** | 无 | 低 | 高 | 确定性操作 |

### 选型决策树

```
任务需求
    │
    ├── 输入输出确定？ ── 是 ──→ 传统代码
    │
    └── 否
        │
        ├── 流程可预设？ ── 是 ──→ Workflow（LLM 作用在部分阶段）
        │
        └── 否 ──→ 完全 ReAct（需要强约束）
```

### 混合架构最佳实践

| 实践 | 说明 |
|------|------|
| **定义边界** | 明确 LLM 能力的边界，如风险检测可用 LLM，但最终处置需要人工确认 |
| **保持确定性** | 确定的业务流程继续用传统代码 |
| **评测驱动** | 切换模型或流程时，依赖严谨的评测 |

### 执行模式方法论映射

| 模式 | 代码映射 | 核心机制 | 适用场景 |
|------|---------|---------|---------|
| **ReAct** | `while + if` | 循环执行：思考→行动→观察，直到完成 | 探索性任务、不确定路径 |
| **Workflow** | `if + elif + else` | 条件分支：根据任务类型选择处理链 | 结构化流程、可预设路径 |
| **LangGraph** | `Workflow + StateNode` | 图结构表达更灵活的条件分支 | 复杂编排、多状态流转 |
| **Plan-Exec** | `for + function call` | 顺序执行：先规划步骤列表，再逐个执行 | 任务可分解、步骤可预设 |

**关键洞察**：
- **ReAct** = 把 Tool 一股脑丢给 LLM，让其自行决定整个业务流程
- **Workflow** = 让 LLM 只作用在流程的部分阶段，限制灵活性以获得确定性提升
- 选择依据：任务确定性和LLM能力的平衡

|-------|---------|-----------|
