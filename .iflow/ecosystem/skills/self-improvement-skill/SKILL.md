# Self-Improvement Skill

> **与 deposition-records.md 的关系**: 本 Skill 是经验沉淀的**触发机制**（何时触发、如何记录），`deposition-records.md` 是经验沉淀的**存储位置**（格式规范、固化机制）。两者配合使用：本 Skill 决定"何时沉淀"，deposition-records.md 决定"沉淀到哪里、怎么沉淀"。

## 核心要点（必须记住）

- **定位**: 自我改进的触发和记录机制，与 `deposition-records.md` 配合使用
- **触发场景**: 6种明确场景，记录到对应位置
- **提升机制**: 广泛适用的学习提升到规范文件
- **自指检查**: 必须验证是否真正执行

---

## 触发场景（何时记录）

| 场景 | 触发条件 | 记录类型 | 记录时机 | 记录位置 |
|------|---------|---------|---------|---------|
| **操作失败** | 命令/操作失败 | ERROR | 立即记录 | deposition-records.md |
| **用户修正** | 用户说"不对..."、"其实..." | LEARNING | 立即记录 | deposition-records.md |
| **功能缺失** | 用户想要但项目没有的功能 | FEATURE_REQUEST | 立即记录 | issues/ |
| **工具失败** | 外部 API 或工具失败 | ERROR | 立即记录 | deposition-records.md |
| **知识过期** | 发现知识过期或错误 | LEARNING | 任务完成后检查 | deposition-records.md |
| **方法改进** | 发现更好的方法 | LEARNING | 任务完成后检查 | deposition-records.md |

---

## 执行流程

```
触发场景发生
     │
     ▼
┌─────────────────────────────────────┐
│ Step 1: 判断场景类型                 │
│ - ERROR: 操作失败、工具失败          │
│ - LEARNING: 用户修正、知识过期、方法改进│
│ - FEATURE_REQUEST: 功能缺失          │
└─────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────┐
│ Step 2: 记录到对应位置               │
│ - ERROR/LEARNING → deposition-records│
│ - FEATURE_REQUEST → issues/          │
└─────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────┐
│ Step 3: 评估是否需要提升             │
│ - 广泛适用？→ 固化到规范             │
│ - 仅当前项目？→ 保留在沉淀           │
└─────────────────────────────────────┘
     │
     ▼
┌─────────────────────────────────────┐
│ Step 4: 自指检查                    │
│ - 我是否真正记录了？                │
│ - 记录内容是否完整？                │
└─────────────────────────────────────┘
```

## 记录格式

### ERROR 记录

```markdown
### 沉淀 N: [错误标题]

**场景标签**: `#ERROR` `#具体标签1` `#具体标签2`

**场景描述**:
[具体错误场景]

**解决方案**:
[如何解决]

**关键洞察**: [一句话总结]
```

### LEARNING 记录

```markdown
### 沉淀 N: [学习标题]

**场景标签**: `#LEARNING` `#correction/knowledge_gap/best_practice` `#具体标签`

**场景描述**:
[具体场景]

**错误本质**:
[为什么会犯错]

**解决方案**:
[如何改进]

**关键洞察**: [一句话总结]
```

### FEATURE_REQUEST 记录

在 `issues/` 目录创建文件：

```markdown
# 功能请求: [功能名称]

**请求来源**: 用户反馈
**优先级**: 高/中/低
**描述**: [功能描述]
**预期效果**: [预期效果]
```

## 提升机制（固化到规范）

| 学习类型 | 提升到 | 示例 |
|---------|-------|------|
| **行为模式** | `start.md` 核心要点 | "先规划后编码" |
| **工作流改进** | `COMMANDS.md` | "两阶段流程" |
| **协作规范** | `endPoint.md` | "自指检查机制" |
| **代码规范** | `CODING_SPEC.md` | "命名语义规范" |

**提升判断标准**：
- AI 是否能在执行时遵守？（是 → 提升）
- 是否重复犯错？（否 → 提升）
- 是否广泛适用？（是 → 提升）

## 自指检查（必须执行）

| 检查项 | 合格标准 | 不合格示例 |
|-------|---------|-----------|
| **场景匹配** | 正确判断触发场景 | 错误分类 |
| **记录完整** | 场景标签 + 描述 + 解决方案 | 只说"已记录" |
| **位置正确** | 写入对应文件 | 没有实际写入 |
| **提升评估** | 判断是否需要固化 | 没有评估 |

**自指检查模板**：

| 我声称的执行 | 实际做了什么 | 是否真正执行 |
|-------------|-------------|-------------|
| xxx | xxx | ✅/❌ |

## 注意事项

1. **立即记录**: 触发场景发生后立即记录，不要等到任务结束
2. **真实记录**: 只记录真实发生的问题，不编造
3. **自指检查**: 记录后必须检查是否真正写入
4. **定期固化**: 成熟后固化到规范，删除沉淀（保留索引）
