# 修改完整性

## 规则 23：修改完整性

**规则内容**：修改代码时必须保持逻辑完整性 → 注释编号连续，变量命名一致；思想：不能删除关键步骤，修改完成后必须检查：步骤是否完整、注释编号是否连续、变量名是否一致、逻辑是否正确

## 为什么需要修改完整性

避免遗漏关键步骤，确保逻辑正确，提高代码质量，降低维护成本。

## 常见错误案例

### 错误1：删除了关键步骤

``` java
public void processOrder(Order order) {
    // 1. 校验订单状态
    if (order.getStatus() != OrderStatus.PENDING) {
        throw new IllegalArgumentException("订单状态不正确");
    }

    // 删除了扣减库存的步骤（关键步骤）

    // 2. 创建支付记录
    paymentService.createPayment(order);

    // 3. 更新订单状态
    order.setStatus(OrderStatus.PAID);
    orderRepository.save(order);
}
```

**问题**：删除了扣减库存的关键步骤，导致库存数据不一致。

### 错误2：注释编号不连续

``` java
public void processOrder(Order order) {
    // 1. 校验订单状态
    if (order.getStatus() != OrderStatus.PENDING) {
        throw new IllegalArgumentException("订单状态不正确");
    }

    // 3. 扣减库存（编号不连续，缺少2）
    inventoryService.deduct(order.getProductId(), order.getQuantity());

    // 4. 创建支付记录
    paymentService.createPayment(order);

    // 5. 更新订单状态
    order.setStatus(OrderStatus.PAID);
    orderRepository.save(order);
}
```

**问题**：注释编号不连续，容易造成理解混乱。

### 错误3：变量命名不一致

``` java
public void processOrder(Order order) {
    // 1. 校验订单状态
    if (order.getStatus() != OrderStatus.PENDING) {
        throw new IllegalArgumentException("订单状态不正确");
    }

    // 使用了不一致的变量名
    OrderDto orderDto = convertToDto(order);
    orderDTO.setUserId(order.getUserId()); // 应该是 orderDto

    // 2. 更新订单状态
    order.setStatus(OrderStatus.PAID);
    orderRepository.save(order);
}
```

**问题**：变量命名不一致，导致编译错误。

### 错误4：遗漏了工作流架构的步骤

**错误**：只修改了数据采集模块的节点处理器，但未检查其他模块是否受影响

**问题**：可能导致工作流架构的完整性破坏，影响整体流程。

### 错误5：遗漏了节点体系的方法

**错误**：实现了业务接口，但只实现了部分方法

**问题**：编译错误，或运行时错误。

## 如何检查

### 检查清单

#### 通用检查清单
- [ ] 步骤是否完整？
- [ ] 注释编号是否连续？
- [ ] 变量名是否一致？
- [ ] 逻辑是否正确？
- [ ] 是否删除了关键步骤？
- [ ] 是否有编译错误？
- [ ] 是否有 IDE 警告？

#### 工作流架构检查清单
- [ ] 数据采集模块的步骤是否完整？
- [ ] 数据处理模块的步骤是否完整？
- [ ] 数据输出模块的步骤是否完整？

#### 节点体系检查清单
- [ ] 是否正确实现了业务接口？
- [ ] 是否正确继承了抽象类？
- [ ] 是否正确实现了所有必需的方法？

### 检查方法

#### 方法1：步骤完整性检查
检查修改的代码是否包含了所有必要的步骤，没有遗漏关键步骤。

#### 方法2：注释编号检查
检查注释编号是否连续，没有跳号。

#### 方法3：变量命名检查
检查变量命名是否一致，没有大小写不一致的情况。

#### 方法4：逻辑正确性检查
检查逻辑是否正确，没有遗漏边界条件和异常情况。

#### 方法5：编译检查
运行 `mvn compile` 检查是否有编译错误。

## 常见误区

1. **以为可以删除关键步骤**：必须确保逻辑完整性，不能删除关键步骤
2. **以为注释编号不重要**：注释编号必须连续，便于理解
3. **以为变量名不一致没关系**：变量名必须一致，避免编译错误
4. **以为只修改当前模块就够了**：修改工作流架构的一个模块时，必须检查其他模块是否受影响
5. **以为实现了接口就够了**：必须实现所有必需的方法

## 最佳实践

### 实践1：修改前规划
修改前先规划好修改的步骤，确保不遗漏关键步骤。

### 实践2：修改后检查
修改后必须检查步骤完整性、注释编号连续性、变量命名一致性、逻辑正确性。

### 实践3：编译验证
修改后必须运行编译检查，确保没有编译错误。

### 实践4：逐步验证
对于复杂的修改，可以逐步验证：
1. 先编译检查
2. 再运行单元测试
3. 最后运行集成测试

### 实践5：使用版本控制
使用 Git 等版本控制工具，可以方便地查看修改历史和回滚。

### 实践6：五大领域架构完整性检查
修改五大领域架构的任何一个域时，必须检查其他 4 个域是否受影响：
- 检查依赖关系是否完整
- 检查数据流是否正确
- 检查状态转换是否正确

### 实践7：节点体系完整性检查
修改节点处理器时，必须检查：
- 是否正确实现了所有必需的方法
- 是否正确继承了抽象类
- 是否正确配置了节点类型
