# 联动完整性

## 规则 4：联动完整性

定义：任何修改都可能产生连锁影响 → 动作：执行任何修改操作时，识别依赖关系并同步处理所有关联项 → 思想：系统是一个整体，必须保证修改后系统一致性

## 适用范围

| 范围 | 包含内容 |
|------|---------|
| 代码文件 | 接口、类、方法、字段、import、注释 |
| 规范文件 | .iflow/ 目录下的所有文件 |

## 执行步骤

1. **识别修改类型**：添加 / 删除 / 修改
2. **识别依赖关系**：谁依赖我、我依赖谁、共享概念、相关文档
3. **同步处理**：调用点、实现类、import语句、注释块、相关文档

## 典型场景

| 操作类型 | 必须同步处理 |
|---------|------------|
| 删除接口方法 | 实现类方法、调用点、import、注释块 |
| 删除类 | 所有调用点、import、相关注释块 |
| 修改方法签名 | 所有调用点 |
| 修改规范文件 | 读取相关文件验证一致性 |

## 技术手段

| 层面 | 手段 |
|------|------|
| 代码层面 | 使用 @Override 注解强制接口与实现同步 |
| 规范层面 | 修改前读取相关文件，修改后验证一致性 |

## 案例

### 案例1：删除接口方法

**背景**：删除 `UserService.deleteUserById()` 方法

**同步处理**：
1. 删除 `UserServiceImpl.deleteUserById()` 实现方法
2. 删除所有调用点
3. 删除未使用的 import 语句
4. 删除相关注释块

### 案例2：修改规范文件

**背景**：修改 `start.md` 流程定义

**同步处理**：
1. 读取 `endPoint.md` 确认流程一致性
2. 读取 `WORKFLOW_SPEC.md` 确认流程一致性
3. 修改后对照验证

### 案例3：删除整个功能模块

**背景**：删除 RAG 功能模块

**同步处理**：
1. 删除所有相关类文件
2. 搜索并删除所有调用点
3. 删除所有 import 语句
4. 删除所有依赖注入字段
5. 运行编译检查
