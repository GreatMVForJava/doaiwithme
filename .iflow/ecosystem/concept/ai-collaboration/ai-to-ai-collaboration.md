# AI-AI 协作

> **定位**: 多AI实例间的协作协议与行为规范
> **核心问题**: 多个AI实例如何有效协作、交接、避免冲突

---

## 定义

AI-AI协作是指多个AI实例在同一项目或跨项目中，通过规范化的协议进行任务交接、上下文传递和冲突解决。

## 三种AI-AI协作场景

| 场景 | 说明 | 典型模式 |
|------|------|---------|
| **串行交接** | AI-A完成部分任务，AI-B继续 | 沉淀→读取 |
| **并行协作** | 多个AI同时处理不同子任务 | 分区→合并 |
| **层级编排** | 主AI分配子任务给子AI | 三宫六院 |

## 协作协议

### 1. 上下文交接协议

**交接方（AI-A）必须输出**：

| 交接内容 | 格式 | 说明 |
|---------|------|------|
| 任务状态 | 完成度 + 未完成项 | 其他AI从断点继续 |
| 关键决策 | 决策 + 原因 | 避免其他AI重复决策或推翻决策 |
| 已知风险 | 风险 + 应对策略 | 避免其他AI踩同样坑 |
| Cache状态 | task-progress.json 快照 | 状态连续性 |

**接收方（AI-B）必须执行**：

| 步骤 | 操作 |
|------|------|
| 1 | 读取 Cache（task-progress.json, deposition-records.md） |
| 2 | 读取交接方的关键决策和已知风险 |
| 3 | 输出"我理解当前状态是..."，等待确认 |
| 4 | 从断点继续，不重复已完成的工作 |

### 2. 并行协作协议

| 规则 | 说明 |
|------|------|
| **分区执行** | 每个AI只修改自己负责的文件区域 |
| **共享只读** | 共享文件只读取不修改 |
| **冲突检测** | 执行前检查目标文件是否被其他AI修改 |
| **合并优先** | 冲突时暂停并请求人类决策 |

### 3. 层级编排协议

三宫六院本身就是AI-AI层级编排的实现：
- 乾清宫（规划AI）→ 坤宁宫（调度AI）→ 六院（执行AI）
- 每层AI有明确的输入/输出规范
- 上下文通过 Cache 文件传递

## 与人-AI协作的区别

| 维度 | 人-AI协作 | AI-AI协作 |
|------|---------|---------|
| 决策者 | 人类 | AI（遵循规范） |
| 确认机制 | ask_user_question | 读取规范 + Cache |
| 冲突解决 | 人类裁决 | 规范优先 + 人类兜底 |
| 上下文传递 | 对话 | Cache文件 + 沉淀记录 |
| 错误恢复 | 人类纠正 | 自检 + 沉淀 + 规范固化 |

## AI 执行检查

| 检查项 | 合格标准 | 不合格示例 |
|-------|---------|-----------|
| **交接完整性** | 输出任务状态+关键决策+已知风险 | 只说"任务已完成" |
| **接收验证** | 读取Cache并确认当前状态 | 不读Cache直接开始 |
| **分区遵守** | 只修改自己负责的文件 | 越区修改 |
| **冲突检测** | 修改前检查文件是否被变更 | 直接覆盖 |
