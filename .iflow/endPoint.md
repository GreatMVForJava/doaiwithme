# endPoint.md - AI 执行详细规范（兜底检查）

> **定位**: 详细执行规范，告诉 AI "怎么做"
> **与 start.md 的关系**: start.md 是入口索引（"要做什么"），endPoint.md 是执行手册（"怎么做"）
> **设计原理**: AI 记忆规律是"前后记忆，中间遗忘"，endPoint.md 在末位确保关键检查不被遗忘

**强制输出模板已在 start.md 中定义，AI 必须填满表格才能进入下一阶段。**

---

## 零、核心流程（强调）

``` text
预检 → 确认 → 规划 → 执行 → 自检 → 沉淀
```

**每步都必须输出，等待人类确认，不可跳过。**

---

## 一、预检（详细规范）

**核心问题：是否有概念阻塞？这是什么类型的操作？需要读取哪些文件？**

### 1.1 执行顺序

| 顺序 | 内容 | 说明 |
|------|------|------|
| 1 | 概念阻塞检查 | 是否有不理解的概念？→ 先读取 `@.iflow/context/concept/GLOBAL_CONCEPTS.md ` |
| 2 | 身份确认 | 读取 `@.iflow/context/identity/ ` 目录，确认身份和用户 |
| 3 | 身份初始化检查 | 检查 user.md 是否已初始化，未初始化则触发询问 |
| 4 | Cache 检查 | 读取 `@.iflow/cache/ ` 目录，检查是否有未完成的任务（Level 0） |
| 5 | 冷启动检查 | 根据场景读取冷启动文档（Level 1/2/3） |
| 6 | 意图判断 | 根据理解的需求，判断操作意图 |
| 7 | 文件读取 | 根据意图映射必须读取的文件列表 |

### 1.2 身份初始化检查（详细）

**检查条件**：读取 `@.iflow/context/identity/user.md `，检查"初始化状态"字段

**初始化状态判断**：
- `✅ 已初始化` → 继续预检流程
- `❌ 未初始化` 或不存在 → 触发初始化询问

**初始化询问流程**：
``` text
AI 输出："检测到用户画像未初始化，请确认以下信息：
1. 您的角色是什么？（如：程序员、产品经理、测试工程师）
2. 您常用的技术栈是什么？
3. 当前项目名称和架构是什么？
4. 您的协作偏好是什么？"

用户回答
    ↓
AI 更新 user.md
    ↓
AI 更新 user.md 中"初始化状态"为"✅ 已初始化"
    ↓
继续预检流程
```

**身份切换场景**：
- 用户说"切换到项目 X"或"切换到用户 Y"
- AI 识别切换意图，读取 `identity/users/` 或 `identity/projects/` 目录
- AI 更新 `user.md` 或项目配置的指向
- AI 重新读取新的用户/项目画像

### 1.2 Cache 检查（首次问候检查）

> **详细规范**: `@.iflow/cache/CACHE_SPEC.md `

**触发时机**：每次对话开始

**检查流程**：

``` text
1. 读取 .iflow/cache/pending-tasks.json
2. 读取 .iflow/cache/skipped-tasks.json
3. 读取 .iflow/cache/task-progress.json
4. 如有待办 → AI 输出未完成任务提醒
```

**输出格式**：

``` text
## Cache 检查
- 待确认任务：x 个
- 跳过的任务：x 个
- 任务进度：x/x

如有待办 → 输出：
"检测到未完成的任务：
- 任务边界：xxx
- 当前进度：x/x
- 跳过的任务：x个

是否继续？[Y/n]"
```

### 1.3 冷启动检查（四层防御）

> **详细规范**: `@.iflow/context/experience/cold-start.md `

**四层防御体系**：

| Level | 名称 | 位置 | 触发时机 |
|-------|------|------|---------|
| 0 | 状态层（Cache） | `.iflow/cache/` | 每次预检 |
| 1 | 项目级冷启动 | `.iflow/context/experience/cold-start.md` | 新项目/新AI |
| 2 | 需求级冷启动 | `app-demand/YYYY-MM-DD/需求名称/requirementColdStart.md` | 新需求 |
| 3 | 任务级执行清单 | 需求文档中的AI执行清单 | 执行任务时 |

**检查流程**：

``` text
1. Cache 检查（已完成）
2. 判断是否需要冷启动：
   - 新项目？→ 读取 cold-start.md
   - 新需求？→ 读取 requirementColdStart.md
   - 继续任务？→ 直接进入意图判断
```

**输出格式**：

``` text
## 冷启动检查
- 项目级：已读取/无需
- 需求级：已读取 @requirementColdStart.md / 无需
- 任务级：已读取执行清单 / 无需
```

### 1.4 意图-文件映射表

| 操作意图 | 必须读取的文件 |
|---------|---------------|
| 修改规范文件 | `@.iflow/start.md `, `@.iflow/endPoint.md `, 相关规范文件 |
| 修改代码文件 | `@.iflow/context/rule/ai-coding/CODING_SPEC.md `, 相关代码文件 |
| 沉淀经验 | `@.iflow/context/experience/collaboration-method.md `, `@.iflow/context/experience/EXPERIENCE_SPEC.md ` |
| 创建文档 | 检查规则8，确认是否允许 |

### 1.5 强制输出模板（必须填空）

> **关键**：AI 必须填满以下表格，否则视为预检未完成

``` text
## 预检

### 1. 四层防御检查（必须输出）
| Level | 名称 | 检查结果 | 是否读取 |
|-------|------|---------|---------|
| 0 | Cache 状态层 | 有/无待办任务 | ✅/❌ |
| 1 | 项目级冷启动 | 是否新项目 | ✅/❌ |
| 2 | 需求级冷启动 | 是否新需求 | ✅/❌ |
| 3 | 任务级执行清单 | 是否需要 | ✅/❌ |

### 2. 身份确认
- 已读取：identity.md / soul.md / user.md
- 用户画像状态：已初始化 / 未初始化

### 3. 概念阻塞
- 是否有概念阻塞：无 / 有（需说明）

### 4. 操作意图
- 意图类型：修改规范 / 修改代码 / 沉淀经验 / 创建文档

### 5. 必须读取文件（勾选）
- [ ] 文件1
- [ ] 文件2

### 6. 已读取摘要（每文件一句话）
- @文件1：xxx
- @文件2：xxx
```

**AI幻觉检查点**：
- 如果 AI 只输出一句话"已完成预检"，视为未完成
- 必须 output 具体的表格和勾选项

### 1.6 强制要求

- 必须先检查概念阻塞，有阻塞先消除
- 必须读取 identity/ 目录确认身份
- 必须检查 cache/ 目录确认是否有未完成任务
- 必须根据场景读取冷启动文档（四层防御）
- 必须先判断意图，再输出文件列表
- 必须实际读取文件，不能省略
- 必须输出文件内容摘要，证明已读取

## 二、确认（详细规范）

**必须输出**：需求理解复述 + 理解边界 + 任务完成条件

### 2.1 执行内容

| 内容 | 说明 | 示例 |
|------|------|------|
| **复述需求** | "我理解您需要..." | "我理解您需要优化数据库查询性能" |
| **理解边界** | 包含什么、不包含什么 | "包含：SQL优化、索引优化；不包含：架构重构" |
| **任务完成条件** | 什么情况下任务才算完成 | "编译通过 + 单元测试通过 + 无IDE警告" |
| **识别模糊点** | 需要进一步确认的内容 | "是否需要考虑并发场景？" |

### 2.2 Cache 操作（必须执行）

> **详见**: `@.iflow/cache/CACHE_SPEC.md ` 第四节

**写入 task-progress.json**：

``` text
确认阶段结束 → 写入任务边界和完成条件

写入内容：
{
  "current_task": {
    "id": "task-xxx",
    "boundary": { "include": [...], "exclude": [...] },
    "completion_conditions": [...],
    "status": "in_progress"
  }
}
```

**触发条件**：
- 任务需要跨对话执行
- 非单次简单问答

### 2.2 任务周期主动机制

**核心原则**：在任务未完成前，AI不退出，保持主动性。

**主动检查点**：
- 任务开始时：明确定义任务边界和完成条件
- 任务执行中：主动汇报进度，遇到问题主动提问
- 任务完成前：主动检查是否满足完成条件
- 任务完成后：主动沉淀经验

**AI主动行为规范**：

| 阶段 | AI主动行为 | 触发条件 |
|------|-----------|---------|
| 任务开始 | 输出"任务边界"和"完成条件" | 每次任务 |
| 任务执行 | 主动汇报进度、主动提问 | 每完成一个子任务 |
| 遇到阻塞 | 主动说明问题、主动提出方案 | 发现问题时 |
| 任务完成 | 主动检查完成条件、主动沉淀经验 | 任务结束时 |

### 2.3 人机协作

``` text
AI 输出理解 → 人类确认或纠正 → AI 更新理解
```

**禁止跳过确认直接执行。**

### 2.4 交互规则（减少不必要的确认）

**原则**：只在需要人类补充数据时才询问，否则默认执行下一阶段。

**规则表**：

| 场景 | AI行为 | 示例 |
|------|--------|------|
| 有需要用户补充的数据 | 输出"需要补充：xxx"，询问 | "需求边界不明确，请确认包含哪些功能？" |
| 没有问题需要补充 | 直接执行下一阶段，不询问 | 预检 → 确认 → 规划（连续执行） |
| 关键操作 | 必须确认 | git commit、git push、创建文件 |
| 任务完成 | 输出完整检查表，等待确认 | 自检完成，是否提交？ |

**错误示例**：
``` text
预检完成。是否进入确认阶段？[Y/n]  ← 不需要询问
确认完成。是否进入规划阶段？[Y/n]  ← 不需要询问
```

**正确示例**：
``` text
预检 → 确认 → 规划 → 执行（连续执行，中途不询问）
执行完成，是否提交？[Y/n]  ← 关键操作需要确认
```

## 五、自检（含心跳检查）- 兜底重点

> **兜底重点**: 自检是防止遗漏的最后一道防线
> **必须逐条输出**，不可省略

**必须输出**：
1. 规则检查表（逐条输出）
2. 自指检查（提出新方法时必须）
3. 心跳检查结果（待办、问题、沉淀）
4. 记忆压缩检查（可选）

### 5.1 强制输出模板（必须填空）

> **关键**：AI 必须填满以下所有表格，否则视为自检未完成

``` text
## 自检

### 一、规则检查表（逐条输出）

| 规则 | 检查结果 |
|------|---------|
| 规则0 | ✅/❌ + 说明 |
| 规则1 | ✅/❌ + 说明 |
| 规则4 | ✅/❌ + 说明 |
| 规则5 | ✅/❌ + 说明 |
| 规则8 | ✅/❌ + 说明 |
| 规则9 | ✅/❌ + 说明 |

### 二、核心原则检查（修改.iflow文件时必须）

| 原则 | 是否遵守 | 说明 |
|------|---------|------|
| 先规划后编码 | ✅/❌ | 是否输出了任务边界？ |
| 最小化上下文负载 | ✅/❌ | 是否只读取了必要文件？ |
| 始终以验证结束 | ✅/❌ | 是否输出了检查表？ |

### 三、自指检查（提出新方法时必须）

**我是否执行了我正在提出的方法？**

| 提出的方法 | 是否执行 | 证据 |
|-----------|---------|------|
| 方法1 | ✅/❌ | 具体执行的证据 |
| 方法2 | ✅/❌ | 具体执行的证据 |

### 四、心跳检查

| 检查项 | 结果 |
|-------|------|
| Cache 任务进度 | x/x |
| 待办事项 | 无/有 |
| issues/ | 无/有 |
| 经验沉淀 | 无需/需沉淀 |
```

**AI幻觉检查点**：
- 如果 AI 输出"已完成自检"但没有具体表格，视为未完成
- 核心原则检查只在修改.iflow文件时需要
- 自指检查需要"证据"，不是简单的✅/❌

### 5.2 自指检查（提出新方法时必须）

**触发条件**：提出新方法、新规范、新流程时，必须执行自指检查。

**核心问题**：我是否执行了我正在提出的方法？

**执行步骤**：
1. 列出提出的新方法/规范
2. 检查自己是否执行了这个方法/规范
3. 如果没有执行，先执行，再提出
4. **终止条件**：只检查一次，检查对象是"方法内容"，不是"检查行为本身"，不递归

**输出格式**：

``` text
### 二、自指检查

**我是否执行了我正在提出的方法？**

| 提出的方法 | 是否执行 | 说明 |
|-----------|---------|------|
| 方法1 | ✅/❌ | ... |
| 方法2 | ✅/❌ | ... |

**发现问题**：[如有]
**改进措施**：[如有]
```

**AI老师的角色**：
- 每次经验都需要沉淀给其他AI学生使用
- 沉淀路径：`.iflow/context/experience/`
- 沉淀内容：场景标签 + 场景描述 + 解决方案

### 5.3 心跳检查（嵌入到每次自检中）

**Cache 操作（必须执行）**：

``` text
自检阶段 → 读取 task-progress.json → 检查完成条件

读取内容：
{
  "current_task": {
    "completion_conditions": [...],

  }
}

检查逻辑：
- 所有条件 status = "done" → 任务完成 → 触发清理
- 有条件 status = "pending" → 任务未完成 → 继续询问
```

**检查清单**：
- [ ] Cache 中是否有未完成的任务？

- [ ] issues/ 是否有新问题？
- [ ] 是否有经验需要沉淀？

**输出格式**：

``` text

|-------|------|
| Cache 任务进度 | x/x（完成/未完成） |
| 待办事项 | 无/有：xxx |
| issues/ | 无新问题/有：问题描述 |
| 经验沉淀 | 无需/需沉淀：内容 |
```

## 六、沉淀（详细规范）

**必须输出**：沉淀内容 + 沉淀路径 + Cache 清理结果

### 6.1 Cache 清理（任务完成时必须执行）

> **触发条件**：任务完成条件全部满足 或 用户明确说"取消任务"

**清理操作**：

``` text
任务完成 → 清理 Cache

清理内容：
1. 删除 pending-tasks.json 中的已完成任务
2. 删除 skipped-tasks.json 中的已完成任务
3. 更新 task-progress.json：
   - 移动 current_task 到 completed_tasks
   - current_task 设为 null
   - 或用户取消：直接清空所有
```

**输出格式**：

``` text
### Cache 清理

| 操作 | 结果 |
|------|------|
| pending-tasks.json | 已清空/保留：xxx |
```

## 八、记忆压缩机制（详细说明）

> **AI 记忆规律**: 前后记忆，中间遗忘
> **压缩目的**: 保证重点记忆，对抗上下文膨胀和遗忘

### 9.1 压缩原理

``` text
AI 上下文结构：
┌─────────────────────────────────────────────┐
│ [首位] 稳定层文件（IDENTITY/SOUL/USER）      │ ← 最容易被记住
├─────────────────────────────────────────────┤
│ [中间] 动态层文件（experience/skills/...）   │ ← 最容易遗忘
├─────────────────────────────────────────────┤
│ [末位] endPoint.md 兜底检查                  │ ← 次容易被记住
└─────────────────────────────────────────────┘
```

### 9.2 压缩触发条件

| 触发条件 | 检查方式 | AI 动作 |
|---------|---------|---------|
| experience/ 文件数 > 10 | 在自检时检查 | 输出"建议合并相似经验" |
| 单个经验文件 > 500 行 | 在沉淀时检查 | 输出"建议拆分专题" |
| issues/ 超期问题 > 7 天 | 在心跳检查时检查 | 输出"建议固化或删除" |
| 单次任务上下文 > 50% | 在执行时感知 | 输出"建议精简加载文件" |

### 9.3 压缩执行流程

``` text
1. 提取核心要点 → 每个文件开头增加"核心要点"章节
2. 合并相似内容 → 多个相似文件合并为一个
3. 归档历史版本 → 保留最终版，历史版本归档
4. 更新索引 → EXPERIENCE_SPEC.md 更新索引
```

### 9.4 核心要点提取规范

**每个动态层文件必须包含**：

``` text
## 核心要点（必须记住）

> 本章节是记忆压缩的核心，AI 读取时优先关注此章节

- 要点1：xxx
- 要点2：xxx
- 要点3：xxx
```

## 十、核心要点回顾（对抗遗忘）

> **兜底重点**: 以下是必须记住的核心要点，在末位重复强调
> **对抗遗忘**: AI 记忆规律是"前后记忆，中间遗忘"，末位强调确保不遗忘

### 10.1 流程要点

``` text
预检 → 确认 → 规划 → 执行 → 自检 → 沉淀
每步必须输出，每步等待确认，不可跳过。
```

### 10.2 心跳要点

``` text
每次任务完成后：
- [ ] 是否有未完成的待办？
- [ ] issues/ 是否有新问题？
- [ ] 是否有经验需要沉淀？
```

### 10.3 记忆压缩要点

``` text
动态层文件必须包含"核心要点"章节
每个核心要点 3-5 个，每个不超过 50 字
```

### 10.4 身份确认要点

``` text
每次预检：
1. 读取 identity/ 目录确认身份
2. 检查 user.md 是否已初始化
3. 未初始化则触发询问流程
```

### 10.5 强制执行机制

> **诚实说明**: 规范本身是"软约束"，无法保证AI一定执行
> **解决方案**: 多层防御机制，尽可能降低错误概率

**多层防御**：
1. **首位强调**: start.md 明确要求"每次任务开始时，必须执行预检"
2. **末位强调**: endPoint.md 在末尾重复关键检查点
3. **待办强制**: 规划阶段必须创建待办列表，否则视为流程未完成
4. **输出物强制**: 每步必须有输出，缺少输出物视为流程未完成
5. **人类确认强制**: 每步必须等待人类确认，未确认不能进入下一步
6. **错误后沉淀**: 每次错误后，反思并沉淀到 experience/

**关键**：例子不能保证执行，只有"多层防御"才能尽可能降低错误概率。
