# 三层信息模型

> **定位**: Token 效率最大化的分层主动获取
> **L2 引用**: @.iflow/ecosystem/skills/SKILLS_SPEC.md

---

## 定义

AI 通过分层主动获取实现 Token 效率最大化，先粗筛再精选。

## 核心原则

- **主动获取**：AI 主动读取文件，而非系统自动注入
- **渐进披露**：按需深入，避免一次性读取全部内容
- **Token 效率**：用最少的 Token 获取足够的上下文

## 三层架构

| 层级 | 内容 | 读取时机 | Token 消耗 |
|------|------|---------|-----------|
| **L0 概览** | name + description | 启动时主动读取 | ~30 Token/技能 |
| **L1 Body** | SKILL.md 主体 | 识别需求后主动读取 | ~500-2000 Token |
| **L2 详细** | references/ 文档 | 需要详细操作时主动读取 | ~1000-5000 Token |

## Token 节省效果

```
一次性全部读取：SKILL.md + 详细文档 ≈ 7000 tokens
渐进读取（只需概览）：description → ~50 tokens
节省：~99%
```

## 使用场景

| 场景 | AI 行为 | 读取内容 |
|------|--------|---------|
| **启动时** | 主动读取所有技能的 L0（概览） | name + description |
| **识别需求后** | 主动读取特定技能的 L1（Body） | SKILL.md 主体 |
| **需要详细操作时** | 主动读取 L2（详细文档） | references/ 文档 |

## AI 执行检查

| 检查项 | 说明 |
|-------|------|
| 是否主动读取了 L0？ | 启动时应读取所有技能的概览 |
| 是否按需读取了 L1？ | 识别需求后才读取特定技能主体 |
| 是否只在必要时读取 L2？ | 避免一次性读取详细文档 |
