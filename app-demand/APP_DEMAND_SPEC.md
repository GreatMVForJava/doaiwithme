# app-demand 目录规范

> **定位**: 业务需求管理目录，AI与人类协作的需求入口
> **命名**: 全大写+下划线，作为当前目录层级的规范
> **关联文件**: [requirementsGuidelines.md](./requirementsGuidelines.md) | [requirementsTemplate.md](./requirementsTemplate.md)

---

## 核心规则

定义：需求是代码的唯一真实来源 → 动作：需求变更必更新文档，文档必关联代码 → 思想：保持需求与代码一致，减少沟通成本

---

## 需求生命周期

### 两阶段模型

``` text
需求拆分阶段 → 需求执行阶段
     ↓              ↓
  理解文档化      代码实现验证
```

| 阶段 | 核心活动 | 输出物 | 参与协作模式 |
|------|---------|--------|-------------|
| **需求拆分** | 人类创建 → AI理解 → 生成文档 | `requirementColdStart.md` | AI自我理解、AI+人协作 |
| **需求执行** | 确认 → 规划 → 执行 → 自检 → 沉淀 | 代码、测试、经验 | AI+人协作、人+人配合、智能人+智能人 |

### 阶段关系

| 关系 | 说明 |
|------|------|
| **拆分是执行的前提** | 需求文档不完整，执行会偏离方向 |
| **执行检验拆分质量** | 执行中发现问题，回溯更新拆分文档 |
| **沉淀是连接点** | 执行经验沉淀后，指导下一次拆分 |

## 协作模式

### 模式分类

| 模式 | 定义 | 适用场景 | 信息流向 |
|------|------|---------|---------|
| **AI自我理解** | AI独立完成理解任务 | 读取需求、理解概念、生成文档 | AI内部 |
| **AI+人协作** | AI与人类双向确认 | 需求确认、方案澄清、进度同步 | 双向 |
| **人+人配合** | 程序员之间的沟通 | 需求评审、代码审查、知识传递 | 双向 |
| **智能人+智能人** | 跨智能人协作 | 交接、协作、对齐 | 双向 |
| **AI+AI配合** | 跨AI实例传递 | 经验沉淀、规则传递 | 间接 |

### 模式应用

#### 需求拆分阶段

| 活动 | 协作模式 | 说明 |
|------|---------|------|
| 人类创建需求内容 | 人+人配合 | 产品、测试、开发之间的沟通 |
| AI读取理解需求 | AI自我理解 | SQ3R阅读法、乔哈里窗识别盲点 |
| AI生成冷启动文档 | AI自我理解 | 依据规范模板生成 |
| 需求确认 | AI+人协作 | 苏格拉底提问、确认理解边界 |

#### 需求执行阶段

| 活动 | 协作模式 | 说明                        |
|------|---------|---------------------------|
| 读取历史沉淀 | AI自我理解 | 读取 .iflow/ecosystem/ 下的经验 |
| 需求确认 | AI+人协作 | 依照 .iflow/start.md 流程     |
| 规划方案 | AI+人协作 | 联动检查、方案讨论                 |
| 代码实现 | AI自我理解 + AI+人协作 | 编码 + 疑问确认                 |
| 代码审查 | 人+人配合 | 程序员之间审查代码                 |
| 交接协作 | 智能人+智能人 | 跨智能人传递上下文                 |
| 经验沉淀 | AI+AI配合 | 当前AI实例 → 未来AI实例           |

## 组织形式

### 目录结构

``` text
app-demand/
├── APP_DEMAND_SPEC.md              # 目录规范（AI专用）
├── requirementsGuidelines.md       # 需求管理准则（共用）
├── requirementsTemplate.md         # 需求文档模板（共用）
└── YYYY-MM-DD/                     # 按日期组织的需求
    └── 需求名称/
        ├── requirementColdStart.md # 需求级冷启动【必须】（共用）
        ├── 产品/                   # 产品资料（人类专用）
        │   └── 产品需求.md
        ├── 测试/                   # 测试资料（人类专用）
        │   └── 测试问题.md
        └── 代码/                   # 代码映射（人类专用）
            └── 代码映射.md
```

### 命名规范

| 命名类型 | 使用者 | 示例 |
|---------|--------|------|
| **中文命名** | 人类专用 | `产品需求.md`、`测试问题.md`、`代码映射.md` |
| **驼峰小写** | AI + 人类共用 | `requirementColdStart.md`、`requirementsGuidelines.md` |
| **大写下划线** | AI专用 | `APP_DEMAND_SPEC.md` |

### 目录命名

| 类型 | 命名规范 | 示例 |
|------|---------|------|
| 日期目录 | YYYY-MM-DD | `2026-02-27` |
| 需求目录 | 中文命名（可含空格） | `支付 demo`、`支付对账优化` |

## 使用方法

### 阶段一：需求拆分

**人类创建需求**：
1. 在 `YYYY-MM-DD/` 下创建需求目录（中文命名）
2. 创建人类专用文件：`产品/产品需求.md`、`测试/测试问题.md`

**AI理解需求**：
1. 读取产品需求.md 和测试问题.md
2. 参考 `requirementsGuidelines.md` 和 `requirementsTemplate.md`
3. 生成 `requirementColdStart.md`

**确认边界**：
- AI输出需求理解，人类确认
- 使用苏格拉底提问澄清歧义

### 阶段二：需求执行

**依照 .iflow/start.md 执行**：

``` text
预检 → 确认 → 规划 → 执行 → 自检 → 沉淀
```

| 步骤 | 活动 | 协作模式 |
|------|------|---------|
| 预检 | 读取规则、理解意图 | AI自我理解 |
| 确认 | 需求理解复述、边界确认 | AI+人协作 |
| 规划 | 联动检查、执行计划 | AI+人协作 |
| 执行 | 代码实现、测试 | AI自我理解 + AI+人协作 |
| 自检 | 对照验收标准检查 | AI自我理解 + 人+人配合 |
| 沉淀 | 更新经验文档 | AI+AI配合 |

### 规范文件说明

| 文件                             | 用途 | 适用阶段 |
|--------------------------------|------|---------|
| `APP_DEMAND_SPEC.md`           | 组织需求目录 | 两阶段 |
| `requirementsGuidelines.md`    | 需求文档准则 | 需求拆分 |
| `requirementsTemplate.md`      | 需求文档模板 | 需求拆分 |
| `.iflow/start.md`              | 执行流程入口 | 需求执行 |
| `.iflow/ecosystem/experience/` | 经验沉淀 | 需求执行 |

## 沉淀原则

### 内容分类

| 分类 | 使用者 | 示例 |
|------|--------|------|
| **共用** | AI + 人类 | `requirementColdStart.md`、`requirementsGuidelines.md` |
| **人类专用** | 人类 | `产品需求.md`、`测试问题.md`、`代码映射.md` |
| **AI专用** | AI | `APP_DEMAND_SPEC.md` |

### 迭代规则

| 变化类型 | 处理方式                               |
|---------|------------------------------------|
| **新增需求** | 创建新目录 `YYYY-MM-DD/需求名称/`           |
| **需求变更** | 更新需求文档，记录变更历史                      |
| **需求废弃** | 移动到 `archive/YYYY-MM-DD/`          |
| **通用经验** | 沉淀到 `.iflow/ecosystem/experience/` |
