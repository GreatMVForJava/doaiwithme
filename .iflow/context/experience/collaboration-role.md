# 协作角色

> **适用场景**: AI与人类协作过程中的角色识别、协作模式选择
> **核心目的**: 明确协作参与者，选择正确的协作模式，提高协作效率
> **核心概念**: 协作角色定义详见 `@.iflow/context/concept/GLOBAL_CONCEPTS.md `（第七节：协作角色）

---

## 一、协作角色定义

> **核心概念已定义**: 详见 `@.iflow/context/concept/GLOBAL_CONCEPTS.md `（第七节：协作角色）
> 本节为详细展开，便于实际应用

### 1.1 基本角色

| 角色 | 定义 | 能力边界 |
|------|------|---------|
| **AI** | 人工智能助手 | 执行、理解、生成、沉淀 |
| **人** | 人类程序员 | 决策、验证、澄清、沟通 |
| **智能人** | AI + 人的组合体 | 决策 + 执行的完整能力 |

### 1.2 角色关系

``` text
     人 ←─────→ 智能人 ←─────→ AI
      │           │           │
      │    AI+人协作    │
      │           │           │
      └─── 人+人配合 ───┘    └─── AI自我理解 ───┘
```

## 二、协作模式分类

### 2.1 五种协作模式

| 模式 | 定义 | 信息流向 | 适用场景 |
|------|------|---------|---------|
| **AI自我理解** | AI独立完成理解任务 | AI内部 | 读取需求、理解代码、生成文档 |
| **AI+人协作** | AI与人类双向确认 | 双向 | 需求确认、方案澄清、进度同步 |
| **人+人配合** | 程序员之间的沟通 | 双向 | 需求评审、代码审查、知识传递 |
| **智能人+智能人** | 跨智能人协作 | 双向 | 交接、协作、对齐 |
| **AI+AI配合** | 跨AI实例传递 | 间接 | 经验沉淀、规则传递 |

### 2.2 模式选择依据

| 判断条件 | 选择模式 |
|---------|---------|
| 任务不涉及人类决策 | AI自我理解 |
| 任务需要人类确认 | AI+人协作 |
| 任务需要程序员间沟通 | 人+人配合 |
| 任务涉及跨智能人交接 | 智能人+智能人 |
| 任务需要跨实例传递经验 | AI+AI配合 |

## 三、模式详细说明

### 3.1 AI自我理解

**定义**：AI独立完成理解任务，无需人类干预。

**适用场景**：
- 读取需求文档
- 理解代码逻辑
- 生成格式化文档
- 执行已确认的方案

**方法工具**：
- SQ3R阅读法：系统理解文档/代码
- 笛卡尔分解：拆分复杂问题
- 乔哈里窗：识别理解盲点

**输出要求**：
- 理解结果可验证
- 盲点需主动暴露

**示例**：
``` text
AI读取产品需求.md → SQ3R阅读法 → 理解笔记
AI阅读核心代码 → 识别类/方法/数据流 → 理解笔记
```

### 3.2 AI+人协作

**定义**：AI与人类双向确认，共同完成决策。

**适用场景**：
- 需求理解确认
- 方案设计讨论
- 进度同步汇报
- 疑问澄清

**方法工具**：
- 苏格拉底提问：澄清模糊需求
- 乔哈里窗：识别信息区域
- 笛卡尔怀疑精神：质疑理解

**输出要求**：
- AI输出理解复述
- AI输出理解边界
- 人类确认或澄清

**示例**：
``` text
## 需求确认
- 需求理解：[一句话概述]
- 包含：[范围内的工作]
- 不包含：[范围外的工作]
- 疑问：[需要澄清的问题]

是否理解正确？
```

### 3.3 人+人配合

**定义**：程序员之间的沟通，AI辅助但不主导。

**适用场景**：
- 需求评审会议
- 代码审查（Code Review）
- 知识传递培训
- 问题讨论会

**AI角色**：
- 记录会议要点
- 提供背景信息
- 整理讨论结果

**输出要求**：
- 会议纪要
- 决策记录
- 待办事项

### 3.4 智能人+智能人

**定义**：跨智能人协作，传递完整上下文。

**适用场景**：
- 任务交接
- 并行协作对齐
- 跨团队协作

**交接内容**：
- 需求上下文
- 代码变更历史
- 待办事项
- 风险点

**输出要求**：
- 交接文档
- 状态同步
- 对齐确认

**示例**：
``` text
## 交接文档
- 需求：[需求概述]
- 进度：[当前状态]
- 待办：[剩余工作]
- 风险：[潜在问题]
- 文档：[相关文档链接]
```

### 3.5 AI+AI配合

**定义**：跨AI实例传递经验，实现知识沉淀。

**适用场景**：
- 经验沉淀
- 规则迭代
- 问题预防

**传递方式**：
- 通过文档传递：`.iflow/context/experience/`
- 通过规则传递：`.iflow/context/rule/`
- 通过问题传递：`.iflow/context/issues/`

**输出要求**：
- 场景标签格式
- 可复用方法论
- 验证结果记录

**示例**：
``` text
## 场景标签
- 触发条件：什么时候会遇到这个场景？
- 问题类型：这是什么类型的问题？

## 场景描述
描述具体的业务场景和上下文

## 解决方案
描述如何解决这个问题

## 关联经验
链接到相关的经验文档
```

## 四、协作模式应用

### 4.1 需求生命周期中的模式应用

| 阶段 | 活动 | 协作模式 | 说明 |
|------|------|---------|------|
| **需求拆分** | 人类创建需求内容 | 人+人配合 | 产品、测试、开发之间的沟通 |
| **需求拆分** | AI读取理解需求 | AI自我理解 | SQ3R阅读法、乔哈里窗识别盲点 |
| **需求拆分** | AI生成冷启动文档 | AI自我理解 | 依据规范模板生成 |
| **需求拆分** | 需求确认 | AI+人协作 | 苏格拉底提问、确认理解边界 |
| **需求执行** | 读取历史沉淀 | AI自我理解 | 读取 .iflow/context/ 下的经验 |
| **需求执行** | 需求确认 | AI+人协作 | 依照 .iflow/start.md 流程 |
| **需求执行** | 规划方案 | AI+人协作 | 联动检查、方案讨论 |
| **需求执行** | 代码实现 | AI自我理解 + AI+人协作 | 编码 + 疑问确认 |
| **需求执行** | 代码审查 | 人+人配合 | 程序员之间审查代码 |
| **需求执行** | 交接协作 | 智能人+智能人 | 跨智能人传递上下文 |
| **需求执行** | 经验沉淀 | AI+AI配合 | 当前AI实例 → 未来AI实例 |

### 4.2 协作流程中的模式切换

``` text
预检(AI自我理解) 
    → 确认(AI+人协作) 
    → 规划(AI+人协作) 
    → 执行(AI自我理解 + AI+人协作) 
    → 自检(AI自我理解 + 人+人配合) 
    → 沉淀(AI+AI配合)
```
