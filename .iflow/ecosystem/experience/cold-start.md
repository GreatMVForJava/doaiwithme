# 冷启动解决方案

> **定位**: 四层防御体系的原理说明 + 协作原则 + 效果评估
> **触发时机**: 新项目启动、新AI接入
> **与 start.md 的关系**: start.md 有流程，本文档有原理

---

## 核心要点（必须记住）

- **四层防御**: Cache状态层(Level0) → 项目级冷启动(Level1) → 需求级冷启动(Level2) → 任务级执行清单(Level3)
- **Cache 是状态层**: 解决"我做到哪里了"（进度）
- **冷启动是初始化层**: 解决"我从哪里来"（背景）
- **协作原则**: 人类提供上下文 + AI主动读取 + 沉淀经验

---

## 一、四层防御体系原理

```
Level 0: Cache 状态层     → 解决"我做到哪里了？"（进度）
    ↓ 每次对话检查
Level 1: 项目级冷启动     → 解决"项目规范是什么？"（通用背景）
    ↓ 新项目/新AI时检查
Level 2: 需求级冷启动     → 解决"需求背景是什么？"（需求背景）
    ↓ 新需求时检查
Level 3: 任务级执行清单   → 解决"具体怎么执行？"（执行步骤）
```

### 各层级说明

| Level | 名称 | 位置 | 触发时机 | 作用 |
|-------|------|------|---------|------|
| 0 | Cache 状态层 | `.iflow/cache/` | 每次预检 | 保证跨对话连续性 |
| 1 | 项目级冷启动 | 本文档 | 新项目/新AI | 通用规范和设计原则 |
| 2 | 需求级冷启动 | `app-demand/.../requirementColdStart.md` | 新需求 | 需求背景和代码位置 |
| 3 | 任务级执行清单 | 需求文档中 | 执行任务 | 具体步骤和验收标准 |

## 二、协作原则

### 人类程序员职责

| 职责 | 具体内容 |
|------|---------|
| 提供完整上下文 | 需求文档、原型图、参考资源 |
| 明确术语定义 | 区分不同语境下的术语含义 |
| 确认理解一致 | AI执行前确认理解，关键节点验收 |

### AI 职责

| 职责 | 具体内容 |
|------|---------|
| 主动读取上下文 | 按顺序读取：项目级 → 需求级 → 任务级 |
| 遵循执行清单 | 按步骤执行，遇到阻塞立即反馈 |
| 沉淀经验 | 执行完成后更新冷启动文档 |

## 三、冷启动效果评估

### 评估指标

| 指标 | 目标值 | 测量方法 |
|------|-------|---------|
| **重复询问率** | <10% | 统计对话中重复问题的比例 |
| **规范符合率** | >95% | 代码审查时统计 |
| **需求理解准确率** | >90% | 用户反馈统计 |
| **首次交付合格率** | >80% | 交付统计 |

### 改进措施

| 问题 | 改进措施 |
|------|---------|
| 重复询问率高 | 完善项目级冷启动内容，补充常见问答 |
| 规范符合率低 | 强化规范说明，增加示例 |
| 需求理解准确率低 | 优化需求冷启动模板，明确关键信息 |
| 首次交付合格率低 | 细化执行清单，增加检查点 |

## 四、常见问题

### Q1: 项目级冷启动和需求级冷启动的区别？

**A**: 
- **项目级**: 跨需求通用，不随单一需求变化
- **需求级**: 需求专属，随需求迭代更新

### Q2: 新AI接入项目时应该阅读哪些文档？

**A**:
1. `start.md`（入口，核心要点）
2. 本文档（项目级冷启动）
3. 具体需求的 `requirementColdStart.md`（需求背景）

### Q3: 如何判断内容应该放在哪一层？

**A**:
- 多个需求都会用到 → 项目级冷启动
- 只有当前需求用到 → 需求级冷启动
- 涉及具体执行步骤 → 任务级执行清单
