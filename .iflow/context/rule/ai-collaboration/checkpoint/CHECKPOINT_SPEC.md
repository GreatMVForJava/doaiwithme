# 检查点规范

> **定位**: 关键操作的检查触发机制
> **使用者**: AI为主，人类参考

---

## 核心原则

**检查点不是禁止执行，而是确保人类介入**

规则8的本质：创建md文件前需要和人类交互确认，而不是禁止创建。

---

## 关键操作检查点

以下操作必须在执行前输出检查，等待人类确认：

### 一、创建 md 文件前

**AI必须输出**：
``` text
检查规则8：未经允许不创建md文档。

待创建文件：
- 文件路径1
- 文件路径2

是否允许创建？[允许/不允许]
```

**人机协作**：AI 输出 → 人类确认 → AI 执行或跳过

---

### 二、git commit 前

**AI必须输出**：
``` text
检查规则6：未经允许不执行git commit。

待提交内容：
- 文件路径1：修改内容概述
- 文件路径2：修改内容概述

是否允许提交？[允许/不允许]
```

**人机协作**：AI 输出 → 人类确认 → AI 执行或跳过

---

### 三、git push 前

**AI必须输出**：
``` text
检查规则6：未经允许不执行git push。

待推送提交：
- commit_id: 提交信息

是否允许推送？[允许/不允许]
```

**人机协作**：AI 输出 → 人类确认 → AI 执行或跳过

---

### 四、任务完成自检

**AI必须输出**：完整规则检查表（逐条输出）

``` text
## 规范自检

### AI_COLLABORATION_SPEC.md（AI协作规范）
| 规则 | 要求 | 检查结果 |
|------|------|---------|
| 规则0 | 修改后自检、修改前同意、经验沉淀复用 | ✅/❌ |
| 规则1 | 先说明理解后讨论 | ✅/❌ |
| 规则4 | 联动完整性 | ✅/❌ |
| 规则6 | 未经允许不执行 git commit | ✅/❌ |
| 规则7 | Markdown代码块格式：三个反引号+空格+语言标识符 | ✅/❌ |
| 规则8 | 未经允许不创建 md 文档 | ✅/❌ |
| 规则9 | 修改后自检 | ✅/❌ |

### CODING_SPEC.md（编码规范）
| 规则 | 要求 | 检查结果 |
|------|------|---------|
| 规则10 | 删除未使用内容 | ✅/❌ |
| 规则13 | 不使用 @Autowired，使用构造器注入 | ✅/❌ |
| 规则17 | Javadoc 注释规范 | ✅/❌ |
| 规则20 | 数据库幂等性 | ✅/❌ |
```

**强制要求**：
- 必须逐条输出所有规则的检查结果
- 任何一条为 ❌ 必须说明原因并修正
- 不能跳过任何规则

**人机协作**：AI 输出自检表 → 人类确认或提问

---

## AI不执行怎么办

### 现象

- AI跳过确认步骤
- AI违反规则（如直接创建md文件、直接提交）
- AI输出不完整

### 解决方法

| 方法 | 说明 |
|------|------|
| 提醒AI | "按照CHECKPOINT_SPEC.md的检查点执行" |
| 明确拒绝 | "不允许，重新执行" |
| 回滚重来 | "回滚到上一个正确状态" |

### 预防措施

每次任务开始时发送：
``` text
依照 @.iflow/start.md 执行，遵守关键操作检查点
```
