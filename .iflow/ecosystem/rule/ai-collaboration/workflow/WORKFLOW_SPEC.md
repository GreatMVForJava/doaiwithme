# 流程规范

> **定位**: AI与人类协作的核心流程定义
> **使用者**: AI为主，人类参考

---

## 核心流程

```text
预检 → 确认 → 规划 → 执行 → 自检 → 沉淀
```

每步都必须输出，等待人类确认。

---

## 零、预检

**核心问题：是否有概念阻塞？这是什么类型的操作？需要读取哪些文件？**

**执行顺序**：
1. **概念阻塞检查**：是否有不理解的概念？→ 先读取 `@.iflow/ecosystem/concept/GLOBAL_CONCEPTS.md`
2. **意图判断**：根据理解的需求，判断操作意图
3. **文件读取**：根据意图映射必须读取的文件列表

**意图-文件映射表**：

| 操作意图 | 必须读取的文件 |
|---------|---------------|
| 修改规范文件 | `@.iflow/start.md`, `@.iflow/endPoint.md`, 相关规范文件 |
| 修改代码文件 | `@.iflow/ecosystem/rule/ai-coding/CODING_SPEC.md`, 相关代码文件 |
| 沉淀经验 | `@.iflow/ecosystem/experience/collaboration-method.md`, `@.iflow/ecosystem/experience/EXPERIENCE_SPEC.md` |
| 创建文档 | 检查规则8，确认是否允许 |

**输出格式**：
```
## 预检
- 概念阻塞：[无 / 有，概念：xxx，已读取：@GLOBAL_CONCEPTS.md，已理解：xxx]
- 操作意图：[修改规范/修改代码/沉淀经验/创建文档]
- 必须读取：
  - @.iflow/ecosystem/rule/RULE_SPEC.md（示例）
  - @.iflow/ecosystem/experience/EXPERIENCE_SPEC.md（示例）
- 已读取摘要：
  - @文件1：核心内容概述
  - @文件2：核心内容概述
```

**人机协作**：AI 自行判断意图，有概念阻塞则主动消除

---

## 一、确认

**必须输出**：需求理解复述 + 理解边界

**执行内容**：
- 复述用户需求："我理解您需要..."
- 说明理解边界：包含什么、不包含什么
- 识别模糊点：需要进一步确认的内容

**人机协作**：AI 输出理解 → 人类确认或纠正

---

## 二、规划

**必须输出**：联动检查清单 + 执行计划

**执行内容**：
- 复用历史经验：读取 issues/ 和 experience/
- 联动检查：识别数据流上下游、共享概念、文档同步
- 执行计划：列出待修改文件、待删除文件、风险点

**人机协作**：AI 输出规划 → 人类确认方案

---

## 三、执行

**必须输出**：修改文件列表 + 编译结果

**执行内容**：
- 创建待办列表跟踪进度
- 按计划修改代码
- 编译验证
- 更新待办状态

**人机协作**：AI 输出执行结果 → 人类执行中反馈（如有）

---

## 四、自检

**必须输出**：完整规则检查表（逐条输出）

**执行内容**：
- 读取 AI_COLLABORATION_SPEC.md 和 CODING_SPEC.md
- 逐条输出所有规则的检查结果
- 消除 IDE 警告
- 确认编译通过

**人机协作**：AI 输出自检结果 → 人类确认或提问

---

## 五、沉淀

**必须输出**：沉淀内容 + 沉淀路径

**执行内容**：
- 判断沉淀类型（业务/协作）
- 输出场景标签格式
- 等待人类确认后执行

**人机协作**：AI 输出沉淀内容 → 人类确认 → AI 执行

---

## 沉淀类型判断

```text
内容是什么类型？
├─ 协作相关（方法论、沟通方式、错误预防）
│   └─ 谁使用？
│       ├─ AI使用 → .iflow/ecosystem/experience/
│       └─ 共用 → .iflow/ecosystem/rule/
│
└─ 业务相关（概念、规则、产品需求）
    └─ 谁使用？
        ├─ AI参考 → app-demand/需求/需求冷启动.md
        └─ 人类使用 → app-demand/需求/业务知识/
```

## 场景标签格式

```markdown
## 场景标签
- 触发条件：什么时候会遇到这个场景？
- 问题类型：这是什么类型的问题？（业务/协作/技术）
- 沉淀类型：应该沉淀到哪里？

## 场景描述
具体场景和上下文

## 解决方案
如何解决

## 沉淀路径
- 文件路径：xxx
- 更新内容：xxx
```

## 检查点机制

> **核心原则**：检查点不是禁止执行，而是确保人类介入

以下操作必须在执行前输出检查，等待人类确认：

### 创建 md 文件前

**AI必须输出**：
```text
检查规则8：未经允许不创建md文档。

待创建文件：
- 文件路径1
- 文件路径2

是否允许创建？[允许/不允许]
```

### git commit 前

**AI必须输出**：
```text
检查规则6：未经允许不执行git commit。

待提交内容：
- 文件路径1：修改内容概述
- 文件路径2：修改内容概述

是否允许提交？[允许/不允许]
```

### git push 前

**AI必须输出**：
```text
检查规则6：未经允许不执行git push。

待推送提交：
- commit_id: 提交信息

是否允许推送？[允许/不允许]
```

### AI不执行怎么办

| 方法 | 说明 |
|------|------|
| 提醒AI | "按照WORKFLOW_SPEC.md的检查点执行" |
| 明确拒绝 | "不允许，重新执行" |
| 回滚重来 | "回滚到上一个正确状态" |

**预防措施**：每次任务开始时发送：
```text
依照 @.iflow/start.md 执行，遵守关键操作检查点
```

## 规则速查

| 规则 | 一句话 | 检查时机 |
|------|--------|---------|
| 规则6 | 未经允许不执行 git commit | git commit/git push前 |
| 规则7 | Markdown代码块：三个反引号+空格+语言标识符 | 创建md文件时 |
| 规则8 | 未经允许不创建 md 文档 | 创建md文件前 |
| 规则9 | 修改后自检 | 任务完成时 |
