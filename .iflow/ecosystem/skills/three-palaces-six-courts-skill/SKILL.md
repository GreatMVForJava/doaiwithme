# Three Palaces Six Courts Skill

## 核心要点（必须记住）

- **三宫**：乾清宫（规划）→ 交泰宫（审核）→ 坤宁宫（调度）
- **六院**：承乾院→ 延禧院→ 永和院→ 景仁院→ 钟粹院→ 景阳院（沉淀）
- **钦天监**：监控机构，输出看板、进度报告、风险预警
- **Cache 绑定**：每个院执行后必须写入 Cache
- **自指检查**：每个院执行后必须检查"我是否真正执行了"

## 三宫详解

### 乾清宫（规划宫）

| 项目 | 内容 |
|------|------|
| **职责** | 需求理解、任务分解、方案设计 |
| **输入** | 用户需求 |
| **输出** | 规划方案（任务理解 + 执行计划 + 完成条件） |
| **等待** | 交泰宫审核、用户确认 |

**输出模板**：
```markdown
## 乾清宫规划方案

### 任务理解
- 用户需求：[复述用户需求]
- 隐含需求：[识别的隐含需求]
- 任务边界：包含 / 不包含

### 执行计划
| 序号 | 子任务 | 负责院 | 预期输出 | 风险点 |
|------|-------|--------|---------|--------|

### 完成条件
- [ ] 条件1

### 等待确认
请交泰宫审核，请用户确认。
```

### 交泰宫（审核宫）

| 项目 | 内容 |
|------|------|
| **职责** | 方案审核、质量把关 |
| **输入** | 乾清宫规划方案 |
| **输出** | 审核结果（通过/封驳） |
| **封驳时** | 返回乾清宫重新规划 |

**审核项**：
- 规划完整性
- 任务边界清晰
- 风险评估充分

### 坤宁宫（调度宫）

| 项目 | 内容 |
|------|------|
| **职责** | 任务调度、进度监控 |
| **输入** | 交泰宫审核通过的方案 |
| **输出** | 调度指令（六院分工） |

## 六院详解（含 Cache 操作）

### 承乾院（理解院）

| 项目 | 内容 |
|------|------|
| **职责** | 理解任务意图、确认执行边界 |
| **输入** | 坤宁宫调度指令 |
| **输出** | 理解摘要 |
| **Cache 操作** | 写入 task-progress.json（理解摘要） |

**真正执行的标准**：
- 输出理解摘要 + 实际写入 Cache

**形式主义错误**：
- 只输出理解摘要，不写入 Cache

### 延禧院（执行院）

| 项目 | 内容 |
|------|------|
| **职责** | 执行具体任务、产出交付物 |
| **输入** | 承乾院理解确认的任务 |
| **输出** | 执行结果 |
| **Cache 操作** | 开始时写入、过程中更新、完成后更新 task-progress.json |

**真正执行的标准**：
- 执行任务 + 产出实际结果（修改文件或确认不需要修改）+ 更新 Cache

### 永和院（协同院）

| 项目 | 内容 |
|------|------|
| **职责** | 协调多任务依赖、解决冲突 |
| **输入** | 延禧院执行中遇到的问题 |
| **输出** | 协同报告 |
| **Cache 操作** | 协调开始时写入、冲突解决后更新 task-progress.json |

### 景仁院（反馈院）

| 项目 | 内容 |
|------|------|
| **职责** | 汇报执行进展、反馈问题风险 |
| **输入** | 各院执行结果 |
| **输出** | 进度汇报 |
| **Cache 操作** | 每完成一个任务更新 task-progress.json，发现问题时写入 pending-tasks.json |

### 钟粹院（审校院）

| 项目 | 内容 |
|------|------|
| **职责** | 审校执行结果、评估质量 |
| **输入** | 景仁院反馈结果 |
| **输出** | 审校报告（通过/不通过） |
| **Cache 操作** | 审校完成后写入 task-progress.json |

**真正执行的标准**：
- 真正检查质量 + 不合格就返工 + 写入 Cache

### 景阳院（沉淀院）

| 项目 | 内容 |
|------|------|
| **职责** | 沉淀执行经验、传承方法论 |
| **输入** | 钟粹院审校通过的结果 |
| **输出** | 沉淀报告 |
| **Cache 操作** | 沉淀完成时写入 deposition-records.md，任务完成时更新 task-progress.json |

**真正执行的标准**：
- 评估是否需要沉淀 + 真正写入（或确认不需要）+ 更新 Cache

### Cache 文件

| 文件 | 用途 |
|------|------|
| `task-progress.json` | 任务进度、执行状态 |
| `pending-tasks.json` | 待确认/待处理任务 |
| `skipped-tasks.json` | 跳过的任务 |

## 自指检查（必须执行）

### 检查模板

```markdown
### 自指检查

| 我声称的执行 | 实际做了什么 | 是否真正执行 |
|-------------|-------------|-------------|
| xxx | xxx | ✅/❌ |
| 钦天监看板 | 是否输出看板？ | ✅/❌ |
```

### 常见形式主义错误

| 错误 | 表现 | 正确做法 |
|------|------|---------|
| **只输出格式** | 输出"理解摘要"格式，不写入 Cache | 输出 + 写入 Cache |
| **虚假进度** | 输出"完成"，实际没执行 | 真正执行 + 产出实际结果 |
| **跳过审校** | 输出"通过"，没有检查 | 真正检查 + 不合格就返工 |
| **角色切换** | 输出各院报告，没有真正执行 | 每个院都真正执行 |
| **缺少钦天监** | 没有输出看板 | 三宫后、每院后输出看板 |

## 踩坑清单

| 坑 | 解决方案 |
|---|---------|
| **只做角色切换** | 每个院必须真正执行，不是输出格式 |
| **忘记 Cache** | 每个院执行后必须写入 Cache |
| **跳过自指检查** | 最后必须输出自指检查表 |
| **虚假进度** | 进度必须反映真实执行状态 |
| **审校走形式** | 审校必须真正检查，不合格就返工 |
| **缺少钦天监看板** | 三宫后、每院后必须输出看板 |
| **未参考角色速查** | 执行前应参考角色速查表确认各院核心行为 |
