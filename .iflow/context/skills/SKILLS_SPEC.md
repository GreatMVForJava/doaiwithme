# Skills 规范

## 定义

Skills 是专业技能的抽象，将专业知识、工作流程、工具使用方式封装成可复用的模块。Skills 通过元数据驱动，按需加载，与工具（Tools）绑定。

**Skills 的作用**：
- 将专业技能标准化、模块化
- 让 AI 能够发现、调用、执行专业技能
- 提供明确的工具使用方式

**Skills 与 Tools 的关系**：
- Skills 是专业技能的抽象
- Tools 是具体的工具函数
- Skills 定义了如何使用 Tools

## Skills 核心概念

### 元数据（Metadata）
元数据是技能的基本信息，被客户端解析并传递给模型，让模型知道有哪些技能可用。

**元数据的作用**：
- 被客户端解析
- 传递给模型
- 让模型知道有哪些技能可用

**元数据的字段定义**：

Skills 的元数据采用 YAML front matter 格式，定义在文件开头。

**必选字段**：
| 字段 | 说明 | 格式要求 |
|------|------|----------|
| `name` | 技能的名称，用于标识和查找技能（必填） | 小写字母、数字和连字符（最多 64 个字符），与文件名和目录名一致 |
| `description` | 技能的功能描述和使用时机，模型用它来决定何时应用技能（必填） | 如果省略，使用 markdown 内容的第一段。最多 1024 个字符 |
| `tools` | 技能使用的工具列表，包括工具名称、用途、优先级（必填） | 工具列表，每个工具包含 name、purpose |

**格式示例**：
``` yaml
---
name: web-search-skill
description: 网络搜索技能，用于搜索网络上的信息，查找概念、技术细节等
tools:
  - name: web_search
    purpose: 搜索网络信息，优先搜索 openai、anthropic、google
---
```

**说明**：
- Skills 的元数据必须包含 `name`、`description` 和 `tools` 三个字段
- `name` 是技能的标识，用于区分和查找技能，与文件名和目录名一致
- `description` 让模型知道技能的功能和使用时机
- `tools` 让模型知道技能需要调用哪些工具，以及每个工具的用途和优先级
- 当前项目的 Skills 主要用于：网络搜索、上下文搜索、代码审查等
- 保持技能文件的简洁性，避免冗余

### 按需加载（On-Demand Loading）
- Skills 只基于元数据（名称和描述）消耗上下文
- Skills 的其余部分按需加载
- 加载通常意味着将其内联到对话中（即 `{技能名称}-skill.md` 的内容被注入为上下文）

### Skills 与 Tools 的关系
- Skills 定义了如何使用 Tools
- Skills 的实现步骤指导模型调用具体的工具
- Tools 是具体的工具函数（如 web_search、fetch、read_file、search_file_content 等）
- 模型按照 Skills 的指导调用 Tools，获得执行结果

## Skills 规范

### 1. 文件命名规范

**格式**：`{技能名称}-skill.md`

**示例**：
- `web-search-skill.md` - 网络搜索技能
- `context-search-skill.md` - 上下文搜索技能
- `code-review-skill.md` - 代码审查技能

### 2. 文件结构规范

每个 skills 文件必须包含以下章节：

``` text
# {技能名称} Skill

## 技能描述
简要描述技能的功能和用途

## 触发条件
在什么情况下应该调用这个技能

## 输入参数
技能需要的输入参数

## 输出结果
技能返回的结果格式

## 实现步骤
具体的实现步骤（可以调用工具）
- 每个步骤必须是具体的、可执行的
- 可以调用工具（如 web search、fetch、read_file、search_file_content 等）
- 步骤之间有明确的依赖关系

## 注意事项
使用技能时的注意事项
```

### 3. 技能描述规范

**格式**：`技能名称：技能功能，技能用途`

**示例**：
- `网络搜索技能：搜索网络上的信息，用于查找概念、技术细节等`
- `上下文搜索技能：搜索项目文档，用于查找项目相关的信息和经验`

### 4. 实现步骤规范

**要求**：
- 每个步骤必须是具体的、可执行的
- 可以调用工具（如 web search、fetch、read_file、search_file_content 等）
- 步骤之间有明确的依赖关系
- 明确说明如何使用 Tools

**格式**：
``` text
### 步骤 1：{步骤描述}
{具体实现，包括如何调用 Tools}

### 步骤 2：{步骤描述}
{具体实现，包括如何调用 Tools}

### 步骤 3：{步骤描述}
{具体实现，包括如何调用 Tools}
```

## Skills 类型

### 1. 工具调用型 Skills
可以调用外部工具（如 web search、fetch 等）

**示例**：
- 网络搜索技能
- API 调用技能
- 文件获取技能

### 2. 文档搜索型 Skills
可以搜索项目文档

**示例**：
- 上下文搜索技能
- 代码搜索技能
- 经验查找技能

### 3. 任务执行型 Skills
可以执行特定任务

**示例**：
- 代码审查技能
- 问题排查技能
- 性能优化技能

## Skills 调用流程

1. **AI 识别需求**：AI 在执行任务时，识别出需要调用 skills
2. **通过 endpoint 入口**：AI 通过 endpoint 中定义的 skills 入口
3. **查找合适的 skills**：在 skills 目录下查找（按文件名和描述）
4. **执行 skills 的实现步骤**：
   - Skills 指导 AI 调用具体的 Tools
   - AI 按照 Skills 的指导调用 Tools
   - 获得执行结果
5. **返回结果**：将执行结果返回给 AI

## Skills 与 Tools 的关系示例

``` text
Skills: context-search-skill.md
  - 技能描述：搜索项目文档
  - 实现步骤：
    1. 接收输入参数（keyword、path、file_filter）
    2. 调用 search_file_content 工具搜索
    3. 分析搜索结果
    4. 返回结果
  - 工具：search_filecontent

AI 调用流程：
1. AI 需要搜索项目文档
2. 通过 endpoint 调用：`skills 搜索项目文档`
3. 查找 Skills：找到 `context-search-skill.md`
4. 执行 Skills 的实现步骤：
   - 按照 Skills 的指导，调用 `search_file_content` 工具
   - 获得执行结果
5. 返回结果：将执行结果返回给 AI
```

## 创建新 Skills

1. **确定技能类型**：工具调用型、文档搜索型、任务执行型
2. **定义技能名称**：使用 `{技能名称}-skill.md` 格式
3. **编写技能描述**：简要描述技能的功能和用途
4. **定义触发条件**：在什么情况下应该调用这个技能
5. **定义输入参数**：技能需要的输入参数
6. **定义输出结果**：技能返回的结果格式
7. **编写实现步骤**：
   - 具体的实现步骤
   - 明确说明如何调用 Tools
   - 每个步骤必须是具体的、可执行的
8. **编写注意事项**：使用技能时的注意事项

## 注意事项

1. **技能描述要准确**：技能描述必须准确反映技能的功能和用途
2. **实现步骤要具体**：每个步骤必须是具体的、可执行的
3. **明确工具使用**：实现步骤必须明确说明如何调用 Tools
4. **步骤之间有依赖**：步骤之间要有明确的依赖关系
5. **输出结果要明确**：输出结果的格式要明确

## 沉淀原则

| 场景 | 沉淀动作 | 示例 |
|------|---------|------|
| 发现新技能需求 | 创建新 skill 文件 | `context-search-skill.md` |
| 技能验证有效 | 更新描述和步骤 | 优化实现步骤 |
| 技能不再需要 | 标记废弃 | 添加废弃说明 |

**核心原则**：技能必须可复用，步骤必须可执行，沉淀必须持续迭代。
