# app-demand 目录规范

> **定位**: 业务需求管理目录，AI与人类协作的需求入口
> **命名**: 全大写+下划线，作为当前目录层级的规范
> **关联文件**: [requirementsGuidelines.md](./requirementsGuidelines.md) | [requirementsTemplate.md](./requirementsTemplate.md)

---

## 核心规则

定义：需求是代码的唯一真实来源 → 动作：需求变更必更新文档，文档必关联代码 → 思想：保持需求与代码一致，减少沟通成本

---

## 组织形式

### 目录结构

``` text
app-demand/
├── APP_DEMAND_SPEC.md           # 本文件（目录规范）
├── requirementsGuidelines.md    # 需求管理准则
├── requirementsTemplate.md      # 需求文档模板
└── YYYY-MM-DD/                  # 按日期组织的需求
    └── 需求名称/
        ├── 需求文档.md           # 主文档【必须】
        ├── 需求冷启动.md         # 需求级冷启动【必须】
        ├── 产品/                # 产品资料
        ├── 设计/                # 设计资料
        ├── 测试/                # 测试资料
        └── 代码/                # 代码映射
```

### 命名规范

| 类型 | 命名规范 | 示例 |
|------|---------|------|
| 日期目录 | YYYY-MM-DD | `2026-02-10` |
| 需求目录 | 驼峰中文 | `报告解读优化` |
| 文档文件 | 驼峰中文 | `需求文档.md`, `测试问题.md` |

## 沉淀原则

### 内容分类

| 分类 | 使用者 | 示例 |
|------|--------|------|
| **共用** | AI + 人类 | `requirementsGuidelines.md`, `requirementsTemplate.md` |
| **人类专用** | 人类 | `产品需求.md`, `测试问题.md` |
| **AI参考** | AI | `需求冷启动.md` |

### 迭代规则

| 变化类型 | 处理方式 |
|---------|---------|
| **新增需求** | 创建新目录 `YYYY-MM-DD/需求名称/` |
| **需求变更** | 更新需求文档，记录变更历史 |
| **需求废弃** | 移动到 `archive/YYYY-MM-DD/` |
| **通用经验** | 沉淀到 `.iflow/context/experience/` |

---

## 使用方法

### 人类创建需求

1. 参考 `requirementsGuidelines.md` 了解规范
2. 复制 `requirementsTemplate.md` 创建需求文档
3. 创建 `需求冷启动.md` 记录上下文

### AI处理需求

1. 读取 `requirementsGuidelines.md` 了解规则
2. 读取需求目录下的 `需求冷启动.md`
3. 确认理解后按清单执行
4. 完成后更新状态和代码映射

### 快速指令

| 指令 | 用途 |
|------|------|
| "创建需求" | 使用模板创建新需求文档 |
| "需求状态" | 查询当前需求进度 |
| "需求验收" | 对照验收标准检查 |
