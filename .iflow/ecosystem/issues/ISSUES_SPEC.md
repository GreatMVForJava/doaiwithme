# issues 目录规范

> **定位**: AI 容易出错的问题暂存区，孵化器而非墓地

---

## 核心要点（必须记住）

- **问题必须流动**：发现问题 → 分析原因 → 验证预防 → 固化迁移 → 清理删除
- **成熟后必须固化**：迁移到规则/方法论，避免重复犯错
- **问题不能堆积**：定期检查，成熟即迁移，过时即删除
- **信号驱动沉淀**：踩坑信号 → issues/ → rule/，形成反馈循环

---

## 信号类型（来源：天猫知识基座）

| 信号类型 | 表现形式 | 触发时机 | 内化目标 |
|---------|---------|---------|---------|
| **踩坑信号** | 错误日志、异常堆栈、调试输出 | AI 执行遇到错误 | **issues/ → rule/** |
| **最佳实践信号** | 成功的解决方案、高效的代码模式 | AI 执行成功后反思 | experience/ |
| **新发现信号** | 新的业务规则、隐藏的依赖关系 | AI 执行中发现 | concept/ |

**本目录（issues/）只处理踩坑信号**，其他信号类型按上表分流。

---

## 一、问题生命周期

``` text
发现问题 → 记录分析 → 转化规则 → 验证成熟 → 清理删除
```

| 阶段 | 操作 | 输出物 | 强制要求 |
|------|------|--------|---------|
| **发现问题** | AI犯错或发现潜在风险 | issues/YYYY-MM-DD-问题关键词.md | 必须 |
| **记录分析** | 描述现象、分析根因、制定预防措施 | 问题描述、根本原因、预防措施 | 必须 |
| **转化规则** | 将预防措施转化为具体规则 | 更新 rule/ 相关文件 | **必须** |
| **验证成熟** | 预防措施经过多次验证有效 | 验证记录 | 必须 |
| **清理删除** | 问题已固化，删除 issues 文件 | 删除对应的 issues 文件 | 必须 |

---

## 二、转化规则环节（核心）

> **核心原则**：发现问题必须转化为规则，形成反馈循环
> **来源**：Harness Engineering - "每当 Agent 犯了一个错误，就花时间去工程化一个解决方案"

### 2.1 转化流程

``` text
问题分析
    ↓
确定预防措施
    ↓
选择固化目标
    ├── 规则层（rule/）→ 每次必须检查
    ├── 方法论层（methodology/method-index.md）→ 方法指导
    └── 概念层（concept/）→ 理解定义
    ↓
更新对应文件
    ↓
验证规则有效性
```

### 2.2 固化目标选择表

| 问题类型 | 固化目标 | 固化文件 | 示例 |
|---------|---------|---------|------|
| **每次必须检查** | 规则层 | `@.iflow/ecosystem/rule/ai-coding/CODING_SPEC.md` | 幂等性检查、注释规范 |
| **协作流程问题** | 规则层 | `@.iflow/ecosystem/rule/ai-collaboration/AI_COLLABORATION_SPEC.md` | 联动检查、封驳机制 |
| **方法论层面** | 方法论层 | `@.iflow/ecosystem/methodology/method-index.md` | 乔哈里窗、笛卡尔 |
| **概念理解问题** | 概念层 | `@.iflow/ecosystem/concept/` | Application Legibility |

### 2.3 强制要求

| 要求 | 说明 | 检查方式 |
|------|------|---------|
| **必须有预防措施** | 不能只记录问题 | 检查 issues 文件是否有预防措施章节 |
| **必须有固化目标** | 必须指定哪个文件 | 检查 issues 文件是否有固化目标字段 |
| **必须更新规则文件** | 问题不能停留在 issues | 检查规则文件是否有对应更新 |
| **必须删除 issues 文件** | 问题固化后必须清理 | 定期检查 issues 目录 |

## 五、文档规范

### 命名准则
- 格式：`YYYY-MM-DD-问题关键词.md`
- 示例：`2026-02-04-设计问题.md`
- 原则：文件名必须体现问题类型，便于 AI 快速识别

### 内容准则
- **问题描述**：清楚描述问题现象
- **根本原因**：分析为什么会出错
- **影响范围**：问题影响了哪些内容
- **解决方案**：如何解决该问题
- **预防措施**：如何避免再次发生
- **固化目标**：计划迁移到哪个规则文件

### 更新准则
- AI执行错误时记录
- 发现潜在风险时记录
- 问题固化后删除
