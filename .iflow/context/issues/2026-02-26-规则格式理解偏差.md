# 规则格式理解偏差

## 场景标签
- 触发条件：在规则定义中添加示例内容时
- 问题类型：规则定义与规则详解混淆

## 问题描述

错误做法：在规则定义中添加详细示例

``` markdown
### 30. Markdown格式
定义：正确的格式支持语法高亮 → 动作：编写 Markdown 文档时，代码块必须使用三个反引号+空格+语言标识符的格式 → 思想：提高文档可读性

正确格式：
- ` ``` text ` - 纯文本
- ` ``` java ` - Java代码

错误格式：
- ` ```text ` - 缺少空格
```

问题：规则定义应该是简洁的一行，详细示例应放在规则详解目录中。

## 根本原因

未理解规则设计规范中的"是什么→做什么→为什么"只定义规则本身，详细内容应在详解目录。

## 解决方案

规则定义：只保留一行 `定义：... → 动作：... → 思想：...`

规则详解：详细示例、案例、最佳实践放在 `{编号}-{名称}/` 目录下

## 预防措施

| 检查点 | 说明 |
|-------|------|
| 规则定义长度 | 规则定义应为一行，不包含详细示例 |
| 内容分层 | 规则定义在 SPEC 文件，详解在目录 |
| 遵循设计规范 | 规则设计规范定义了"是什么→做什么→为什么" |
