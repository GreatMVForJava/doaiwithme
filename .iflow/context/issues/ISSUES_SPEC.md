# issues 目录规范

> **定位**: AI 容易出错的问题暂存区，孵化器而非墓地

---

## 核心指导原则

定义：issues 是问题孵化器，用于暂存新发现的、尚未成熟的问题模式 → 动作：发现问题→分析原因→验证预防措施→固化到规则/方法论→清理 issues 文件 → 思想：问题必须流动，不能堆积；成熟后必须固化，避免重复犯错

---

## 一、问题生命周期

``` text
发现问题 → 记录分析 → 强制改进 → 验证成熟 → 固化迁移 → 清理删除
```

| 阶段 | 操作 | 输出物 |
|------|------|--------|
| **发现问题** | AI犯错或发现潜在风险 | issues/YYYY-MM-DD-问题关键词.md |
| **记录分析** | 描述现象、分析根因、制定预防措施 | 问题描述、根本原因、预防措施 |
| **强制改进** | 修改规范文件，增加预防机制 | 规则/流程/检查点的改进 |
| **验证成熟** | 预防措施经过多次验证有效 | 验证记录 |
| **固化迁移** | 迁移到规则或方法论 | 更新 RULE_SPEC.md 或 collaboration-method.md |
| **清理删除** | 问题已固化，删除 issues 文件 | 删除对应的 issues 文件 |

---

## 二、强制改进环节

**核心原则**：发现问题必须改进，不能只记录不解决

**触发条件**：每次 AI 违反规则或犯错时

**必须执行**：
1. 分析问题根因
2. 确定改进目标（规则/流程/检查点）
3. 修改对应文件，增加预防机制
4. 验证改进是否有效

**改进目标选择**：

| 问题类型 | 改进目标 | 改进方式 |
|---------|---------|---------|
| **规则存在但未执行** | 增加强制输出环节 | 在流程中增加必须输出的步骤 |
| **规则不完整** | 完善规则内容 | 更新规则描述，增加具体动作 |
| **规则缺失** | 新增规则 | 在 AI_COLLABORATION_SPEC.md 中增加新规则 |
| **方法论缺失** | 新增方法论 | 在 collaboration-method.md 中增加新方法 |

**禁止行为**：
- 只记录问题，不改进
- 改进后不验证效果
- 改进不关联具体规则或流程

## 四、文档规范

### 命名准则
- 格式：`YYYY-MM-DD-问题关键词.md`
- 示例：`2026-02-04-设计问题.md`
- 原则：文件名必须体现问题类型，便于 AI 快速识别

### 内容准则
- **问题描述**：清楚描述问题现象
- **根本原因**：分析为什么会出错
- **影响范围**：问题影响了哪些内容
- **解决方案**：如何解决该问题
- **预防措施**：如何避免再次发生
- **固化目标**：计划迁移到哪里

### 更新准则
- AI执行错误时记录
- 发现潜在风险时记录
- 问题固化后删除

## 五、使用方式

### AI 读取
``` text
任务开始前 → 读取 issues 目录 → 检查是否有类似问题 → 避免
```

### AI 写入
``` text
发现问题 → 分析原因 → 记录到 issues → 制定预防措施 → 验证成熟后固化
```
